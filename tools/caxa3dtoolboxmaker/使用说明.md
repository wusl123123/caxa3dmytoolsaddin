# caxa3dtoolboxmaker 使用说明

## 这是什么

CAXA 3D 标准件库 `.XML` 配置文件的**独立可视化编辑器**（独立 EXE，不进 CAXA 进程、不依赖 ICAPI）。
按用户 2026-11-19 需求制作，参考 `全牙外六角螺栓_8.8级-发黑_碳钢_GB／T5783.{ics,XML,xlsx}` 这套样本。

## 怎么运行

双击 `bin\x64\Release\net48\caxa3dtoolboxmaker.exe`（编译产物直接从此路径取，不再单独建 dist 副本；依赖 .NET Framework 4.8，Win10/11 自带）。
启动后 XML / ICS 地址栏**留空**，不再预置样本路径；点「浏览」会**动态反查系统安装后的 CAXA 3D ToolBox**（`%LOCALAPPDATA%\CAXA\CAXA 3D\<版本>\<语言>\ToolBox`，参考 `caxa3dmytoolboxbak` 的反查链），不写死用户名 / 版本号 / 语言；多个版本取版本号最高者，同版本优先 `zh-CN`。找不到 ToolBox 时退到 `%LOCALAPPDATA%\CAXA`，再退到程序目录。也可把 XML 路径作为命令行参数传入。

## 五个区域（电子表格编辑）

| 区域 | 能做什么 |
|---|---|
| 文件区 | **XML / ICS / CACHE 三个地址栏**（XLSX 地址栏与比对区已按用户要求删除）。**三栏自动联动**：选 XML ↔ 选 ICS 按同目录同名文件互选（XML→同名 .ics，ICS→同名 .XML）；CACHE 自动填 XML/ICS 所在文件夹**上一级**目录内的 `.cache`。只填确实存在的同名文件（否则留空）；选完 `.cache` 自动加载目录索引页（**可编辑并写回**，见下） |
| **规格表 DataTable（电子表格）** | C# 直接读 XML 在内部建表：行号列（行标题）+ 加粗列头 + 网格 + 交替行色；**首列「螺纹规格」冻结**，横向滑动时规格名常驻；**带水平滚动条**。双击单元格编辑；工具栏 **＋新增行 / ＋新增列 / －删除行 / －删除列 / ↺重新加载**。增删的行列**返填回 XML**（新增列在弹窗输入属性名，写入每个 Row；删除列按当前选中列）。**增删列同时联动参数表**：新增列在参数表追加同名参数行（沿用 SC 模板默认值），删除列在参数表删除对应参数行（按 Dimension/Custom_property/Display_name 匹配） |
| 参数表 ConfigureTable | 22 个参数 × 12 个属性列，可编辑 `AddtoDisplayName`、`Grid_item_state` 等（显示名定制，规则第 46 节） |
| 族信息 CurNodeInfo | 12 个字段可编辑：`name`/`display_name`/`user_name`/`GUID`/`ICSName` 等 |
| **目录索引 .cache（可编辑写回）** | 2026-11-21 新增只读解析、当日再升级为**可编辑**：解析 ToolBox 类目级 `.cache` 索引（`<Root><FolderList><Folder name=… display_name=… type="TB_PART" GUID="{…}" protected=…>`），按属性并集建列显示全部 Folder 条目（首列冻结、双向滚动条）。**双击单元格直接改** name / display_name / type / GUID / protected；工具栏「＋ 新增条目 / － 删除条目 / **保存 .cache**」——保存走保格式写回 + 时间戳自动备份，未改动的字节原样保留。「打开族XML」= 打开 `.cache` 同目录下与 `name` 同名文件夹里的族 XML（优先同名 .xml，唯一 xml 也认；目录不存在 / 0 个 / 多个歧义一律按**第三态**提示，不猜）。「↺ 重新加载」重读盘上索引 |

底部按钮：打开文件 / 保存 XML（自动备份）/ 导出规格 CSV / **导出表格(Excel)** / **导入表格(Excel)** / 关闭。
编辑流程：选 XML → 规格表 Tab 里增删改行列 → 点「保存 XML（自动备份）」返填写盘。

**Excel 导入/导出**（2026-11-20 新增，零依赖）：
- **导出表格(Excel)**：把当前规格表导出为 `.xlsx`，格式**完全参照 CAXA 标准件库导入模板 `123.xlsx`**——行1 零件名、行2 GUID、行4 22 列中文表头、行5 填写说明、行6 起数据。列名按 `Dimension→Display_name` 映射（如 `l→公称长度`、`d→公称直径`；`螺纹规格`/`SC图号` 等本身是中文则原样）。**11-21 起 B1 零件名/B2 GUID 一律取 `.cache` 中当前族对应行**（按 XML 所在文件夹名 + 族 GUID 定位；定位不到/有歧义则拒绝导出并点名，第三态不臆造），不再直接取族信息。需先加载 `.cache`（三栏联动会自动填 CACHE 地址栏并加载）。
- **导入表格(Excel)**：选一个上述格式的 xlsx，按**中文表头名**反查回规格表列（不依赖列顺序），从第6行读数据覆盖规格表（保存 XML 后写入）。表头需含「螺纹规格」列才识别。**11-21 起导入前强校验**：Excel 的 B1 零件名/B2 GUID 必须与 `.cache` 对应行**一致**（GUID 忽略花括号/大小写，name 忽略首尾空白/大小写）；不一致、`.cache` 无对应行或有歧义一律**拒绝导入**并在状态栏点名差异（第三态，不假成功）。校验通过后才同步结构：Excel 比当前规格表多出的列会新增列并在参数表追加同名参数行，Excel 缺少的列会从规格表和参数表一并删除，Excel 数据行数增减直接反映为规格表行数增减（保存 XML 后一并落盘）。
- 实现用 `System.IO.Packaging` + `System.Xml` 零依赖读写 OOXML（无 NuGet、无 Excel COM），见 `XlsxIO.cs`。

## 关键设计（为什么不这样改会出问题）

1. **保格式序列化**：不用 `XmlDocument` 重写（会改自闭合标签、属性顺序、换行、BOM），而是字符串级解析 + 定点重建。自检 `--selftest` 验证"未编辑时 Render 输出与原文逐字节一致"。
2. **UTF-8 无 BOM + CRLF**：与原 XML 完全一致，避免 CAXA 解析差异。
3. **保存前自动备份**：备份到 exe 同目录的 `_backup_原始数据\`（即 `bin\x64\Release\net48\_backup_原始数据\`），文件名带时间戳，写坏可回滚。
4. **ics 内无 GUID**：实测该 ics 任何编码/端序都搜不到 GUID（规则第 46 节只登记了来源路径串）。界面比对区已移除，但此取证结论仍由内核自检 `--selftest` 用 `MetaProbe` 验证，**不假判一致**。
5. **文件名不一致是真实结论**：样本 XML.ICSName 是当前长名，ics 内部却刻着旧名 `全牙外六角螺栓-GB／T5783.ics`（该件改过名）。该结论同样保留在内核自检断言中。
6. **增列/增行返填机制**：表格列顺序 = `doc.RowKeys`。新增列追加到 `RowKeys` 并给每个 Row 补空值属性，删除列从 `RowKeys` 和每个 Row 同步移除；`XmlCore.Render` 按 `RowKeys` 过滤重建每个 `<Row ...>`，所以新增/删除的列会原样写回 XML。自检 `--selftest` 含 6 条专门断言（列数 ±1、XML 可重载、行内容可读、删除列属性消失）。
7. **删除行用当前单元格**：`CellSelect` 模式下 `SelectedRows` 恒为 0，删行改取 `CurrentCell.RowIndex`（坑点第 4 节 #13）。
8. **行标题冻结**：net48 的 DataGridView 没有 `FrozenColumnCount`（那是 .NET Core 才有），冻结首列要用 `Columns[0].Frozen = true`（坑点 #15）。横向滚动时首列规格名常驻，配合行号列构成"行标题"。
9. **xlsx 零依赖读写**：`System.IO.Packaging` 在 `Package.Dispose()` 时**自动生成 `[Content_Types].xml`**，绝不能手动 `CreatePart("/[Content_Types].xml")`，否则保存时抛"由于指定的文件名已在使用，无法创建文件"（坑点 #24）。xlsx 无 BOM、UTF-8、字符串走 sharedStrings（与 `123.xlsx` 一致，CAXA 易识别）。
10. **.cache 保格式写回**（2026-11-21）：`CacheCore.Load` 除解析外还捕获 4 段原文结构（`Prefix`/`Inner`/`FolderSep`/`Suffix`），`Render` 只重排 Folder 属性、片段原样拼接——未编辑时逐字节 round-trip 不变（selftest 断言）。改值只动目标属性，GUID 等字段不伪造；新增条目只写有值的列；写盘前时间戳备份到 `_backup_原始数据\`，UTF-8 无 BOM + CRLF。编辑用 `XmlDocument` 解码中文/实体，但**写回不用 XmlDocument**（会改标签形态），保格式靠字符串级重建。

## 工程布局（.NET Framework 4.8，SDK 风格多文件）

与 `caxa3dmytoolsaddin\tools\caxa3didcskill` 同款布局，源码平铺在工程根：

| 文件 | 职责 |
|---|---|
| `caxa3dtoolboxmaker.csproj` | SDK 风格工程：net48 / WinExe / UseWindowsForms / x64 / LangVersion 10.0 |
| `Program.cs` | 入口 + 自检分流（`--selftest` / `--uitest`，输出重定向到 `_dump\*.txt`） |
| `Diagnostics.cs` | 唯一日志出口（文件 + 界面事件，线程安全） |
| `MainForm.Designer.cs` | `partial class`：控件声明 + `InitializeComponent`（纯布局） |
| `MainForm.cs` | `partial class`：业务逻辑（加载/填充/保存/比对/导出） |
| `XmlCore.cs` | XML 保格式内核（`Attr`/`CheckState`/`XmlCore.Doc`） |
| `MetaProbe.cs` | ics 内部名 / xlsx GUID 三方比对探针 |
| `XlsxIO.cs` | xlsx 零依赖读写（OOXML：sharedStrings + sheet1，导出 CAXA 标准件库模板格式） |
| `CacheCore.cs` | ToolBox `.cache` 类目索引读写（Root/Version/FolderList，属性保序 + 列并集；Raw+结构片段保格式 round-trip，Save 备份 + UTF-8 无 BOM） |
| `SelfTest.cs` | 内核自检 + 界面离屏验证（含 Excel 导出/导入 round-trip 断言） |

## 自检

```
bin\x64\Release\net48\caxa3dtoolboxmaker.exe --selftest  # 内核自检：解析/比对/保格式 round-trip
bin\x64\Release\net48\caxa3dtoolboxmaker.exe --uitest    # 界面自检：控件/数据/坐标/截图
```

单 EXE 双入口（WinExe 无控制台，输出写到 `bin\x64\Release\net48\_dump\selftest.txt` / `uitest.txt`），退出码 0 = PASS。

## 重新编译

```
dotnet build caxa3dtoolboxmaker.csproj
```

输出 `bin\x64\Release\net48\caxa3dtoolboxmaker.exe`（0 警告 0 错误）。交付产物直接从 bin 取，不再建 dist 副本。`Microsoft.NETFramework.ReferenceAssemblies` 包已在 NuGet 缓存，无需联网。旧的 `build.py` + `src\caxa3dtoolboxmaker.cs`（csc 单文件版）保留作历史归档，不再参与编译。

## 边界

- 本工具只编辑 XML，不改 ics。若改显示名后 CAXA 重启把 XML 冲回默认值，需按规则第 46.3 节做 ics 内部等长字节替换破回写（本工具未实现该写操作，避免误伤几何）。
- 遵循已否决路线：不做整族改名（否决 101）、不追求零前导空格（否决 102）。
