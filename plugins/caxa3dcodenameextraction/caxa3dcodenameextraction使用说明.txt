带图改名及图号分离  使用说明
============================================================

一、前提：CAXA 属性模板里要有 SC 四类字段（用户自行加载一次）
------------------------------------------------------------
图号分离回填的是自定义属性「SC图号 / SC名称 / SC规格 / SC材料」，
请确认 CAXA 3D 的属性模板里已预置这四个字段：
  · 属性模板：CAXA 3D → 工具 → 属性模板（自定义属性模板）→ 导入贵司模板。
  · 没有这些字段时，插件会新建同名属性并写入，但设计树/BOM 的显示列不一致，
    看起来像“没写进去”。
  · 本插件不捆绑、不覆盖、不删除任何 CAXA 配置文件；卸载插件也不影响它们。

二、安装与运行前提
------------------------------------------------------------
  1. 本插件不是单独登记的 Add-in，它是集合体 caxa3dmytoolsaddin 的一个子插件：
     安装/卸载都在集合体仓库根目录 C:\code\ICAPI\caxa3dmytoolsaddin\ 双击
     安装.bat / 卸载.bat（deploy.ps1 / restore.ps1）。CAXA 功能区只有「我的工具箱」
     一枚按钮，本插件是它窗口里「1. 常用插件」列的一格。
     编译：改完源码在集合体根目录跑 powershell -ExecutionPolicy Bypass -File build.ps1
     （它会带上本插件与 src\plugins\caxa3dcodenameextraction\ 的暂存）。
  2. CAXA 3D 2027 及以上，选项里开启“同名 ics/exb 联动”（本地保存同名零件与图纸）。
  3. 旧工程（改名前 ics/exb 不同名）需先手工转存一次，让两者同名。
  4. 图纸环境 CRX 桥：集合体 安装.bat 已经把 caxa3dcodenameextraction.crx 拷进
     CAXADraft\bin 并在 Modules\CxAutorun.cx 里登记自己那一行，正常装完重启 CAXA 即可。
     只有换机/CAXA 重装/登记被别的安装器抹掉时才需要手工补：点界面「注册CRX」
     （自动请求管理员权限），或直接运行 caxa3dcodenameextraction-register-crx.ps1。
     缺 CRX 的典型现象：改名能成，但图纸一直不关、等到超时。

三、入口与主窗口按钮
------------------------------------------------------------
  1. 入口：功能区「我的工具箱」→ 主工具箱窗口「1. 常用插件」列 →
     点「带图改名及图号分离」打开主窗口。
     主窗口按钮（2026-11-05 与 caxa3ddiffrename 对齐后的实机口径，逐个从 MainForm.cs 读出的文字）：
       顶部工具条：窗口前置 / 图号分离规则 / 使用说明 / 刷新连接 / 注册CRX / 卸载CRX / 保存日志 / 清理日志
       主体第一行：图号分离开关（_btnSep）· 带图独立 · 重命名v2.0 · 手动图号分离 ·
                   钣金件设计环境设默认 · 工程图标题栏设默认 · 停止
                   （「图纸环境预热」在「窗口前置」正下方，底色即状态灯：绿＝CRX 探针在／已进过图纸环境，
                    红＝冷态，此时开图纸有崩的风险）
       主体第二行：改名替换零部件 · 钣金件尺寸填写 · 更新工程图链接文件 · 零部件重新生成
       主体第三行：更新3dbom
       日志区占满窗口剩余高度（_txtLog Dock=Fill）。
     集合体差异一条：窗口顶部那行连接状态红字标签（_lblConnection）按集合体规则**隐藏**，
     功能与判定逻辑没删，选中件的信息照样从「原零件名」框与「存在工程图/不存在工程图」标记看。
     （2026-11-05 口径：设计环境功能区上不再有第二枚按钮；「带图独立」不再是独立窗口，
     它是主窗口里的一个按钮 —— 独立窗口 DiffRenameForm.cs 只做选区校验与现场取证，
     本插件工程里没有带它，入口少一枚、功能一个没少。）
  2. 流程互斥闸门照旧：同一时刻只允许一条流程在跑，重复点按钮会被占用提示挡住，
     等它结束或点「停止」。

四、操作步骤
------------------------------------------------------------
  1. 启动 CAXA 3D 2027，打开包含 ics / exb 的文件夹工程（设计环境.ics）。
  2. 功能区点「我的工具箱」→「1. 常用插件」列点「带图改名及图号分离」打开主窗口。
     若要在 3D 环境里反复选零件，先点「窗口前置」，窗口会锁定在最上层；再点一次解锁。
  3. 在 3D 环境中选中一个零部件：
       - 集合体版本按「不显示连接状态行」的口径（窗口顶部那行红字标签是隐藏的，
         选中到的是谁，看「原零件名」框与它右侧的“存在工程图 / 不存在工程图”标记）。
       - 「原零件名」框显示 “零部件.ics” 表示有外部链接（可操作）。
       - 显示 “零部件(虚拟)” 表示虚拟零部件，必须先另存为外部 ics 才能重命名。
       - 原零件名右侧显示“存在工程图 / 不存在工程图”。
  4. 新零件名会自动填入原零件名（如需复制原名，选中后 Ctrl+C 或用右键菜单）；若这个件的外链文件名
     与零件名已经不一致（刚做完「带图独立」或「改名替换零部件」），自动填的是**外链文件名**，
     状态栏显示“外链已是 X.ics，元素名还是 Y，点「重命名v2.0」即可对齐”。
     把新名按规则写好（例如 我的_100x20_Q235A_GB123），右侧显示“零件不存在”为绿色通路；
     显示红字“零件名已存在”时按钮不可点，请换名——唯一例外：那个 ics 正是当前选中件自己的
     外链文件时不算重名（替换/独立流程本来就会先复制出这个文件，收尾靠改名对齐）。
  5. 选择“分离规则”（下拉项来自 caxa3dcodenameextraction图号分离规则.txt）。
     下拉框右侧的「自动图号分离」按钮默认开启（蓝色）；点一下变白即关闭，
     关闭后「重命名v2.0」只走改名链、不回填 SC 属性，也不校验段数；再点一下恢复开启（蓝色）。
     规则下拉框为固定宽度，不随窗口拉伸，按钮始终紧邻其右可见。
  6. 点「重命名v2.0」（原「重命名」按钮升级，11-05）：它不再只是改名，而是**按选中件的类型
     自动串起一条联动链**，链上每一步用的就是界面上那颗同名按钮的本体实现，口径完全一致。
     先认类型（认不出/不在范围直接中止，不猜）：
       · 零件(type=1)  ：重命名v2.0 → 更新工程图链接文件
       · 装配体(type=2)：重命名v2.0 → 更新工程图链接文件 → 更新3dbom（这一步在链里会保存并关闭图纸）
       · 钣金件(type=20)：重命名v2.0 → 钣金件设默认 → 更新工程图链接文件 → 标题栏设默认
     第一步「重命名v2.0」本体走 **V2.0 反转时序**（迁自 caxa3dexbtracker 的「重命名-V2.0 功能联动版」）：
       ① 双准入闸：必须是外链件，且当前场景文档 ≠ 它的外链源文件（不满足直接拒绝，不改任何东西）；
       ② 新名**只认界面上的「新零件名」框**（11-05 用户口径：中途那个「输入新零件名」弹窗已去掉，
          不再拦一次流程）—— **图号分离就在这一步做**：
          按界面「自动图号分离」开关与所选规则，先把 SC图号 / SC名称 / … 写进当前选中的件，
          再开始改名。闸没过就一个字段都不会写；框是空的就直接中止（绝不拿旧名当默认值），
          链后面的破坏性步骤一律不接。原弹窗里的「选中 / 外链源 / 将执行 ①②③④」说明改记日志
          （v2: 开头那几行），点按钮之前先看清要做什么。
       ③ 元素改名 set_Name → ④ 父场景另存成新 ics（外链指向随之落到新文件）→
          ⑤ 复核外链确实跟到新名 → ⑥ 旧 exb 改名成新名（File.Move）→ ⑦ 删除旧 ics；
       ⑧ 保存当前场景文档，把新的外链指向落盘（不补这一发，关掉场景重开就回到旧指向）。
     成功判据只看日志里那一行「═══ 结论（外链件…）」——它是四路回读全过之后才印的；
     准入闸拒绝、取消、中途失败都没有这行，链会在第一步就中止并说明后面几步未执行。
     改名框由本步专用哨兵应答（带约束的外链件，CAXA 自弹的改名框只能答「取消」，
     答「是」会被宿主按旧链接回写、整笔回滚 —— 实机 11-02 14:49 定案），
     不走通用代点。
     已知边界：V2.0 只换文件名、不换目录；链的后续步骤靠"新名 + 改名前那个目录"定位，
     定位不到就中止该步并说明，不会往别的件上改。
  7. 「带图独立」（位于「重命名v2.0」左侧，与它同尺寸）：把选中的外链零件从共享链接中独立出来。
     前置：必须是外链件，且“外链文件名 = 零件名”（如 设计环境.ics - 零件A(外链)，零件A.ics 同名）。
     「新零件名」填 零件B。点按钮后**一键串起那三个按钮的逻辑**，每步用的就是它们各自的实现
     （单独点按钮和走这条链，口径完全一致）：
       ① 前置校验（外链件 + 外链文件名=零件名 + 新零件名合法 + 目标不重名），不满足直接弹提示，
          不做任何修改。
       —— 第一步「替换零部件」——
       ② 把 零件A.ics 与同名 零件A.exb 一起复制到「设计环境.ics 所在文件夹」，改名 零件B.ics / 零件B.exb
          （两个目标先全量校验再动手，任一已存在即中止，绝不覆盖）；
       ③ 自动投递并代点 CAXA 原生「替换零件/装配」面板（含两张业务框：选未展开项再点确定），
          把**这一个元素**的外链指向 零件B.ics；
       ④ 遍历设计树验证：确有元素外链指向 零件B.ics 才算替换成功；没验证上就中止并说明
          「复制出的新文件仍在文件夹内」，不会继续往下改名。
          钣金件同样可以走这条链（实机 11-02 13:35 折弯板→折弯板44 全链成功，替换后设计树
          仍报 钣金零件(type=20)）；前提是那两张业务弹窗真选到了条目，日志里要有
          「LinkPickDialog: 第 1 次尝试，已选中…」，若打的是"4 秒内没选到条目"警告则要人工核对类型。
       —— 第二步「改名」（仍是 V1 路线，不是上面那颗 v2.0 按钮）——
       ⑤ 按界面「自动图号分离」开关回填 SC 属性，把元素名从 零件A 改成 零件B，再保存设计环境 ics，
          修成“零件B.ics - 零件B”。
          V1 = set_Name + Save，让 CAXA 2027 的同名联动自己把文件改成新名；
          「带图独立」的文件复制与换链接已经做完，这里只差名字对齐，所以保留 V1
          （换成 V2.0 的反转时序会把刚换好的外链再另存一遍，属于重复动作）。
       —— 第三步「更新工程图链接文件」——
       ⑥ 打开 零件B.exb → 派发「改变链接文件」→ 自动把图纸外链指到 零件B.ics → 保存并关闭图纸。
          目标文件夹内没有 零件B.exb 时这一步自动跳过，日志会明说“只完成替换与改名”。
     其它仍指向 零件A.ics 的同链接件不受影响。
     已知边界：复制出的 零件B.exb 内部 3D 引用仍指向 零件A.ics（本插件不改写 exb 内部数据）；
     图纸里那张「改变链接文件」表格改的是**图纸对 ics 的外链**，与内部引用是两回事。
     ★ 变化说明（11-02）：本按钮早先走的是元素级另存回链 IZPart/IZAssembly::SaveAs(回链=真)，
       现已改为上面这条三步链。SaveAs 回链没有被删除，只是不再是「带图独立」的主路线；
       它曾被视为"钣金件唯一保类型路线"，11-02 13:35 实机证明替换路线对钣金件同样保类型。
  8. 「钣金件设计环境设默认」（只对钣金件生效，点击后直接执行、不弹确认框）：
     在 3D 中选中钣金件后点该按钮，自动执行该件的独立 .ics：
       ① 打开 → ② 展开 → ③ 展开件名改为“展开+成品件名” → ④ 配置还原默认
       → ⑤ 保存 .ics → ⑥ 关闭 .ics
     不涉及工程图；整条流程可随时点「停止」中止（停止不会强行保存、也不会关图）。
  9. 「工程图标题栏设默认」（点击后直接执行、不弹确认框）：
     选中零部件（其文件夹内有同名 exb）后点该按钮，自动执行：
       ① 打开同名 exb → ② 派发“标题栏-右键-设置3D信息”，自动选缺省配置并确定
       → ③ 保存并关闭工程图
     每一步的兜底等待不超过 10 秒，超时即判失败并提示，不会强行保存或关图。
     两个新按钮都可用「停止」中止，界面提示分「已停止 / 失败 / 完成」三支。
  10. 「手动图号分离」（只分离、不改名；任意零部件均可，含虚拟件，无外部 .ics 限制）：
     选中零部件后点该按钮，按当前“分离规则”把名称拆段并回填 SC 属性，然后保存。
     名称来源：优先用「新零件名」输入框内容；为空则用原零件名。
     段数与规则不符时弹提示，不做任何修改。与「自动图号分离」开关无关，随时可用。
 11. 「钣金件尺寸填写」（位于「钣金件设计环境设默认」正下方，只对虚拟钣金件生效）：
     在 3D 设计树中选中「文件名.ics---零件名（虚拟）」的钣金件后点该按钮：
       ① 校验：必须是钣金件（类型 20）、非外部链接、名称不含“展开”、文件名=零件名
       ② 读材料（自定义属性「材料」，缺失回退零件材料名）与板厚（板料属性 mm）
       ③ 找展开件「展开<零件名>」（设计树 → GetFlatPart → Unfold）
       ④ 读展开件最小包围盒：最大边=长、次大边=宽、最小边须等于板厚（±0.1mm，
          否则中止且不写属性）
       ⑤ 回填 SC规格=长x宽、SC材料=<材料>板T=<板厚>（写后回读校验）
       ⑥ 钣金设计环境恢复默认配置（必要时先 Refold）→ 复核属性 → 保存
     尺寸单位 mm、保留 1 位小数并去掉末尾 0。规则文件 caxa3dsheetsizewriteaddfix.txt
     与插件同目录；可随时点「停止」中止（停止不强行保存）。
 12. 「改名替换零部件」（位于「手动图号分离」正下方，原名「替换元素探针」）：只做替换这一步，不改名、不分离、不保存；日志与主程序合并。
     前置校验与「带图独立」完全相同（外链件 + 外链文件名=零件名 + 新零件名=零件B）。
     它把用户的手工链路逐步自动化：
       ① 复制 零件A.ics → 零件B.ics（目标已存在即中止）
       ② IZSelectionMgr::AddElementToSelection 把选中件重新加入 CAXA 活选择集
          （原生命令的帮助串是「替换选择的外部链接零件/装配」，没有活选择它安静地什么都不做）
       ③ 投递 WM_COMMAND 53851 叫出「替换零件/装配」面板（等价右键 外链管理→替换零件/装配）。
          投递目标必须是 CAXA 主框架（类名 Afx: 开头的顶层窗口）；日志里的
          PostReplacePartCommand: hwnd 就是它——插件自己的窗口号（WindowsForms10.*）是无效的。
       ④ 找到面板里的「导入零件/装配」条目并代点 → 文件框自动填入 零件B.ics 并点「打开」。
          定位一律**先锁「属性」pane**（class=BCGPControlBar…，id 实机五次取证恒为 59474：
          13:05 / 13:50 / 13:54 / 14:37 / 15:19），在它的子树里按窗口文字找
          （class=Button 且带文字，主通道 + BM_CLICK），找不到再对这个 pane 走 MSAA
          （pane 根遍历，配额 1200 节点）。面板开没开看 pane 的可访问性子数：**空闲 2 / 打开 5**。
          全框架级的扫描被**严格节流**：每 5 次轮询、或 pane 一时定位不到时才做一次，
          命中后自动把 pane 句柄重新锚定——不再每轮遍历 3 万多节点。
          「等文件框出现」这种判据已删掉（代点器 0.26 秒就填完点掉，永远等不到），
          改为等 PopupAutoYes 的点击计数增加。
       ⑤ 提交：按「代价小、精度高」依次试五条路子，全部只在 pane 内进行——
          pane 内带文字的确定类按钮 → **pane 根 MSAA 的「确定」**（pane 内用包含匹配，
          因为「确定(&O)」归一化后是「确定(o)」；实机 15:19 生效的就是这一条，只遍历 2 个节点）→
          绿色对勾的几何点击（相对 pane 左上的三组偏移 (+13,+12) / (+8,+9) / (+19,+16)，
          由 MSAA 矩形算出：`确定 36,220 22x22` 的中心减去 `pane 34,219`；同级「取消」从相对 x=+24
          起，所以候选 x 严格 <24，且每个候选先做命中窗口校验——命中的必须是 pane 或其子孙，
          绝不把点丢到 3D 视图或「取消」上）→
          沿父窗口链投 IDOK → 给焦点窗口投回车。往主框架盲投 IDOK/回车那两级已删除。
          注意 MSAA 条目的**动作名语言混杂**（命令条是英文 [Press]、滚动条是中文 [按]），
          所以只按名称匹配，绝不按动作名匹配。

          框没办完），随后自动回落，不需要你做任何事。
       ③ 进图纸环境：走本工程的预热纪律（先用**专用空图纸**「caxa3d图纸环境预热.exb」焐热，
          再开业务 exb，见第 13 条①）。**不许在冷态直接 OpenFile2 开业务 exb**
          —— 带 3D 视图链接的业务图纸冷态直开会在 dataexchange.dll 崩掉整个 CAXA（坑 148）；
          专用空图纸没有这条链接路径，实机 3~4 秒焐热、没崩。打不开就中止并让你手工开一次。
       ④ 派发 CX_DFT_Update3DBom（经 CRX 桥的 CMD:SENDSTR 通道）。
       ⑤ 「更新3D明细」对话框由后台哨兵自动处理：勾「更新」→ 点「确定」（时限 60 秒）。
          ★ 跑这一步时本工具窗会**自动沉到 Z 序底**：哨兵是按屏幕像素找那个复选框的，
          窗口常态置顶会压在宿主对话框上面，哨兵抓到的全是自己窗口的像素（实机 17:10 连点 7 次无反应）。
          流程结束（含失败/超时）后自动索回；另有 800 毫秒看门狗兜底，绝不把窗口永久留在后面看不见。
       ⑥ 权威完成信号 = CRX 报 `commandEnded | CX_DFT_Update3DBom`（那张模态框关掉它才结束）。
          等不到就判失败：**不保存、不关图**，把还开着的对话框交还人工。
       ⑦ 收尾分两种口径（这是有意设计的差别）：
          · 单点本按钮 → 图纸**保持打开**，明细就在图上看，不保存、不关闭；
          · 在「重命名v2.0」联动链里（装配体那条链的第三步）→ 保存并关闭这张 exb，回到设计环境。
     状态行三配色：绿 = 哨兵已勾「更新」并点「确定」；黄 = 框被别人关了、本工具没代点（结果不由本工具负责）；
     红 = 没勾上「更新」或 60 秒内没出现那张框。
     整条流程可用「停止」中止；停止时不强行保存、不关图。

五、图号分离规则
------------------------------------------------------------
格式：<规则名>.间隔符"<分隔符>"----"<属性1><分隔符><属性2>..."
  示例  A自制件.间隔符" "----"SC图号 SC名称"        零件名按空格分两段

七、卸载
------------------------------------------------------------
  · 插件：集合体仓库根目录 C:\code\ICAPI\caxa3dmytoolsaddin\ 双击 卸载.bat（restore.ps1），
    CAXA 必须先退出。四个登记点（bin DLL、Config\IronCad.Addin.config、IronCad.exe.manifest、

    本子插件的 DLL 与暂存目录随之消失，不影响其它子插件共存。

    绝不整体还原共享 .bak；CAXADraft\bin\caxa3dcodenameextraction.crx 一并删除。
    注意：登记点留着、.crx 文件被删 = CAXA 启动期 LoadLibrary 原生 AV，两者必须同时摘。
